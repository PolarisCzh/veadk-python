# Studio 创建 MPA 时单次上传 YAML

[English](2026-09-23-per-creation-yaml-upload.md)

- 变更 ID：`per-creation-yaml-upload`
- 创建/修订日期：2026-09-23
- 状态：已实现；本地验证完成，云上/浏览器验证待执行
- 组件：[Studio MPA 创建](../../../specs/studio-mpa-creation/README.zh.md)
- 确认：用户于 2026-09-23 要求上传 YAML 仅用于本次创建。可选的角色问题尚未回复时，仅管理员可上传作为保守的安全边界。

## 背景与证据

当前 `GET /web/mpa-creation/config` 只读取 `VEADK_MPA_CREATE_CONFIG` 或 `mpa-create.config.yaml`。云上 Studio 没有该文件时无法创建。`POST /web/mpa-creation/tasks` 只接收较小的 JSON 请求，并把服务端选定的路径交给子进程。任务服务使用本地 SQLite 和进程内 supervisor；VeFaaS 实例消失时，现有任务本来就会中断。YAML 可能含密钥和服务端环境变量引用。上传到全局路径或浏览器/session storage 会扩大暴露范围，并影响其他创建。

## 目标与非目标

- 允许已授权的 Studio 管理员在 MPA 创建弹窗选择 YAML，仅用于本次创建；默认服务端配置缺失时也可以使用。
- 创建任务前校验上传配置，将原始字节准确绑定到任务，并在成功、失败、取消或拒绝提交后清理临时内容。
- 保持现有服务端配置和 CLI 路径不变。
- 不把 YAML 存入浏览器存储、任务 SQLite、日志、Runtime 输出或 Studio 全局配置；不自动准备缺失的 PostgreSQL、IAM、模型和网络依赖。
- 不改变现有任务 supervisor 的跨实例/重启恢复契约。

## 场景与需求

- **FR-1：** 默认配置缺失时，管理员选取不超过 256 KiB 的 UTF-8 `.yaml`/`.yml` 文件后，可以只用该文件创建。UI 显示文件名及上传/校验错误，不显示文件内容。
- **FR-2：** YAML 无效、超限、地域不符或使用不支持的字段时，服务端在建任务前拒绝。上传配置中的 `managed.template-file` 和 `managed.credential-file` 必须拒绝，因为浏览器不能提供可信的服务端配套文件。
- **FR-3：** 非管理员不得上传配置；有智能体管理权限的其他用户仍可使用服务端配置创建。
- **FR-4：** 合法上传后，任务获得包含所提交字节、权限为 0600 的私有临时文件。直到子进程结束，路径由任务拥有；所有终态和启动前失败路径均删除文件。持久任务输入仅含摘要，不含 YAML 或密钥。
- **FR-5：** 相同 request ID 和相同输入/YAML 摘要保持幂等；更换 YAML 则冲突。响应丢失或弹窗重开后，浏览器需重新选择文件；文件不进入 session storage。
- **FR-6：** 选择文件后，留空的 MPA/Worker 镜像字段使用上传文件中的默认值，而不是服务端配置。选择文件时只清空未经用户修改的服务端预填镜像值；用户主动修改的镜像仍是显式覆盖。

## 设计与契约影响

弹窗沿用现有输入框和按钮样式、原生文件输入，并明确显示文件名和校验消息。现有配置响应增加非敏感 `uploadAllowed` 字段。`POST /web/mpa-creation/tasks` 保持 JSON 兼容，并可选接收 `configYaml` 文本；仅上传请求提高请求体上限。服务端先执行现有智能体管理权限检查，上传时再做管理员校验。校验语法、managed 结构、地域、服务端依赖和不支持的文件引用。权限为 0600 的临时文件放在任务存储旁边，而不是全局配置路径。任务服务负责清理，包括重复提交和异常路径。子进程继续读取路径。现有 CLI 和未上传配置的 API 调用不变。

上传配置仅对本次任务覆盖服务端配置。选择文件时，尚未手工修改的服务端预填镜像值清空，从而沿用上传配置的默认镜像；用户显式编辑保留。不增加上传预检接口或永久配置更新。

任何接口均不返回配置内容。上传不能代替 `DEPLOYMENT_DATABASE_ADMIN_URL`、`SHARED_APIG_DATABASE_URL`、云凭据/IAM 角色等服务端依赖。VeFaaS 实例中断仍会中断现有 supervisor；配置只在该任务生命周期内绑定，并非新增持久任务系统。刷新页面后文件选择不会保留。

## 风险、审查与交付

设计审查已核对管理员权限边界、请求大小、幂等清理、错误脱敏和双语一致性。异常路径测试发现任务接管前临时文件未清理的问题；修正后测试通过。现有配置契约允许 YAML 引用服务端环境变量，因此只允许可信管理员上传。云上端到端验证需要服务端数据库 URL 和已准备的账号；本地测试不能证明云端依赖。仅批准设计不代表批准云上部署。2026-09-23 本地检查：78 个相关 Python/CLI 测试通过，其中路由到子进程的贯通测试证明子进程读取并删除了本次上传的原始文件；1215 个前端单测和 31 个 Vitest 测试通过；前端构建、打包资源校验、国际化校验、改动文件 Ruff 检查及密钥扫描通过；Python 和前端增量行覆盖率分别为 96%、97%。更广的 Python 回归为 4873 通过、8 跳过、2 个预期失败、2 个失败；两个失败均为现有 `test_service.py` 的 flat-mode 用例使用 `agent`，而未修改的 `mpa_provision.py` 校验要求 `mi-[0-9a-z]{12}`。两个改动的后端/任务文件通过 Pyright；现有大型 `cli_frontend.py` 在本次接线以外仍有 36 个类型错误。真实浏览器和云上端到端验证仍为 not_run。
